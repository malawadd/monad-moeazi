# Validation and Promotion

Inject crash around every latch/inventory/call/receipt boundary; schedule/approval/
signing races; uncertain submission; partial/late fill; open TWAP/trigger; misleading
local revoke; OAuth ambiguity; remaining position/collateral/withdrawal; insufficient
gas; reorg/provider disagreement; signer nonce/address reuse; stale/duplicate/reordered
activities; cross-tenant substitution; owner decline; and evidence hold.

## Thresholds

- 100% post-latch risk-increasing requests rejected.
- Every inventory item reaches verified terminal evidence or explicit residual.
- Zero cleanup step re-enables stopped capability.
- Zero duplicate confirmed external effect under retry.
- Zero `fully_terminated_verified` with unknown/residual obligation.
- Same request/revision reproduces plan and step identities.
- Latch remains effective through Temporal/provider outage.

Shadow UI and fake venue/signers only. Measure stop-latch time, completion time and
orphaned schedules/orders/grants/reservations. Any percentage requires a fixture
baseline.

Kill or redesign for local pause/revoke presented as completion, residuals hidden,
reopening compensation, automatic financial/owner action, early reservation release,
evidence deletion, signer-address reuse, model control or generic unchecked cancel-all.

## Baseline, datasets, and sample requirements

The baseline is the current repository behavior or the same frozen plan with this
feature disabled. Datasets begin with versioned local fixtures, adversarial cases and
chronological replay that satisfies Evidence Lifecycle and Usage Rights. Deterministic
safety invariants are checked on every enumerated case, not a statistical sample. Any
percentage or quality hypothesis requires a preregistered power analysis and held-out
chronological cohort; an underpowered result is inconclusive. Promotion requires every
feature-specific threshold plus replayability and cost/latency bounds. One hard-gate or
safety-invariant breach triggers kill/demotion and preserved evidence.
