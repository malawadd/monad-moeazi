## Independent execution

With `MOEAZI_TEST_POSTGRES_DSN` restricted in each DB harness to `postgresql+asyncpg://postgres:postgres@127.0.0.1:15432/moeazi_q3_20260930`, `pytest agent-service/tests -k stage2 -q` passed **120/120**, zero skips, 805 unrelated tests deselected. The lone warning is the environment's Starlette TestClient/httpx deprecation. The focused TypeScript finance projection and handler tests passed **7/7**. The Q2 recorded replay/native subset passed **43/43** and actual SQL056 storage **2/2**; these counts are subsets of the 120 Python passes, not additive. All test data in this run were synthetic or preserved recorded public market responses. The ignored local captures must be present for recorded-data tests; those tests skip when absent and a future green summary without the corpus cannot inherit Q2 qualification.

After the 120-test run, the focused proof-negative module passed **6/6**, including cross-experiment proof and reservation isolation. The two-phase Redis recovery script passed against the disposable database; it is a controlled operational check, not a pytest case or an additional native financial test. Root's final repository-root Python suite passed **892 tests, 33 skipped**; the TypeScript suite passed **277** and the build passed.

Q2 fault cases include venue-specific identity despite reused symbols, wrong/coerced decimals, invalid size step and price rule, crossed/unsorted books, changed source event content/rights/time, duplicate sequence identity, gaps, future availability, stale books, unapproved rights and false finality. The immutable SQL056 boundary rejects caller-edited normalized price/time despite unchanged native raw bytes. A `+03:00` account snapshot with nested position fields roundtrips by canonical UTC hash. The source clock stepped during one runtime spot capture; a later spot capture had stable local request duration but its provider event led receipt by 1.046 seconds and still quarantined. The unaltered BTC runtime sample had a stable local request interval, event 553.742 ms before receipt, and replayed as one snapshot-only observation. This does not certify sustained source/host clock synchronization.

Q3 arithmetic used native integer or exact Decimal values. The hand oracle and actual SQL journal both verify two partial spot buys, a third-asset ETH fee, a sale, collateral/funding/gas/transit, deposits/withdrawals, cash-flow adjustment and exact full reversal. The pure oracle verifies a perpetual contract multiplier and mark/funding separation; the database test verifies generic postings and does **not** certify perpetual position valuation or native settlement. Direct SQL055 tests reject fractional/nonfinite/overflow units, accept exact >2^53 and bounded 78-digit integers, prevent committed history edits and balanced append, and abort empty/unbalanced transactions at commit.

Account observations admitted into finance were explicit **experiment fixtures**; a real native wallet/venue snapshot writer, complete perpetual position valuation, external source finality, production policy approval and funded execution remain gates. The Q2 corpus rights are `internal_qualification_only`, not a commercial distribution grant. Continuous clock/source readiness remains unresolved, so future observations must keep strict event/availability admission. The recorded BTC pass is one sample, not an uptime claim.

The controlled Redis check proves recovery for one synthetic hold and account, not sustained failover under live concurrency. A database-unavailable read failed closed. The synthetic bridge established one end-to-end projection publication/recovery behavior and one timing observation, not sustained projection latency. A future operational acceptance run should use a preregistered latency threshold and live-scope native evidence before funded authorization. Any unresolved financial discrepancy, missing native observation or stale policy continues to block new funded authorization.
