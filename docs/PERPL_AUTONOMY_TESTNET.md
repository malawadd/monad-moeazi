# Perpl Testnet autonomy

Perpl is a separate Perp venue on Monad Testnet (chain `10143`). New Perpl runs use AUSD and real Perpl Testnet markets. The previous mock Perp venue uses Circle testnet USDC and MZA/MZB/MZG pool prices; its existing runs and test tools remain separate and visible. Mock Spot autonomy is also unchanged.

Read [LOCAL_STACK.md](../LOCAL_STACK.md) before starting the local stack. The [standalone acceptance report](PERPL_TESTNET_REPORT.html) distinguishes predicted examples from verified balances, fills, and receipts.
To repeat the three BTC cycles with a fresh Mera-approved run, use the [manual direct-run guide](REPEAT_PERPL_DIRECT_CYCLES.md).

The [contract deployment guide](../backend/contracts/monad-testnet/deployments/PERPL_STRATEGY_VAULT.md) and [verified Perpl manifest](../backend/contracts/monad-testnet/deployments/manifest.perpl.strategy.testnet.json) describe the deployed factory at `0xCF0fd3c3FEd28d40bd739FcE26FD7CC7d923b80e`. On 2026-10-07, a Mera-approved 100 AUSD run created vault `0x0Bf216DE213BFF8279C8d0c87cE154A0807f6192` and Perpl delegated account 964, completed three capped BTC cycles with finalized fills, and returned 99.732661 AUSD after owner stop. ## Execution transports

New enrollment selects `perpl-direct-testnet-v1`: the operator calls the Perpl exchange through the owner's delegated account and pays MON gas. Public, keyless Perpl endpoints provide market context and executable depth. The exchange contract, finalized receipts, and finalized account state decide whether an order executed and whether a position changed. Direct runs do not enroll an API key or enable API order forwarding. The signed version-2 mandate binds transport `1` to the vault; transport `2` is reserved for the retained API adapter. An active run cannot change transport. The direct path has its own default-off `MONAD_TESTNET_PERPL_DIRECT_EXECUTION_ENABLED` gate in addition to the action, broadcast, operator, and Perpl autonomy gates.

Direct run activation grants the operator's delegated account the current `execOrder` and `execOrders` selectors explicitly. The live Testnet factory currently creates accounts whose default allowlist lacks those selectors; this was confirmed on a local Monad fork. The vault turns API forwarding off for direct runs. For API runs it enables forwarding and follows the Origin and API-key flow.

## API transport prerequisite

Perpl API-key enrollment requires Perpl to whitelist the HTTPS `Origin` used by the API transport. The intended origin is `https://moeazi-monad.kiyan.finance`. On 2026-10-07, the public Testnet `/api/v1/api-key/payload` endpoint returned HTTP 400 when called with that origin. It returned HTTP 200 without an `Origin`; the API adapter still refuses enrollment until the origin-bearing request succeeds. This prerequisite does not apply to the verified direct orders. Perpl's [integration guide](https://github.com/PerplFoundation/api-docs/blob/main/integrations.md) describes the whitelist requirement.

The Agora faucet sent 10,000 AUSD to the local Mera test wallet in [finalized transaction `0xec01…02ac`](https://testnet.monadscan.com/tx/0xec01e8c5e708e2cb56796c76f2d170a5bfdbc4b9a6f0d76897079d2b9c6e02ac). That is **wallet funding only**; it is not a Perpl account deposit or trade. No private wallet or API key belongs in this repository.

### Public Perpl coverage without a key

The Origin requirement does not block public market data. From `backend/`, run `node scripts/check-perpl-public.mjs` to check the Testnet context, all-market and single-market tickers, order-book depth, candles, market and all-market funding history, announcements, and public WebSocket subscriptions. On 2026-10-07, eight markets, ten bid and ask levels in market 16, and 61 one-minute candles were observed without an API key. Seven of eight WebSocket streams were accepted; Testnet returned `404` for the documented `gas-stats@10143` stream. These are market observations, not user account data or fills. Perpl's [REST reference](https://github.com/PerplFoundation/api-docs/blob/main/rest-endpoints.md) and [WebSocket reference](https://github.com/PerplFoundation/api-docs/blob/main/websocket.md) distinguish public endpoints from authenticated trading and account endpoints. Direct onchain orders are a separate path noted in Perpl's README; this adapter's requested WebSocket and REST trading path still requires an enrolled trade key.

## User approval and run lifecycle

The user selects Perp → Perpl, chooses AUSD amount and duration, and reviews the exact AUSD transfer, predicted strategy vault, delegated account, eligible live markets, exposure and leverage bounds, direct transport, operator trading scope, and settlement behavior. One Mera unlock signs the exact funding transaction and versioned run mandate. A new run requires fresh approval. Direct routine orders use the gas-paying operator through the delegated account; no Perpl API key or per-order passkey prompt is needed. Future API runs use a per-run trade key held in ignored local secret storage.

The strategy vault is owned by the Mera wallet and owns the Perpl delegated account. The operator can trade but cannot withdraw user AUSD. Per-order caps are enforced by Moeazi's backend, **not by Perpl's contracts**. The backend's default market-order slippage cap is 100 bps, separate from Perpl's live venue maximum, and is shown in the setup review. The account's collateral and positions remain at Perpl; a run cannot switch transports while a position is open. On stop or expiry, the system must cancel pending orders, close exposure, reconcile receipts and balances, revoke operator access, and return withdrawable AUSD to the Mera owner. If any step fails, the app shows incomplete settlement and retains owner recovery. Owner recovery can return AUSD left at a deterministic vault after failed activation; after stop or expiry, an available-collateral recovery checks fresh finalized Perpl account state and refuses to bypass open positions or order locks.

Activity and Perp status distinguish accepted for forwarding, submitted, partially filled, filled, finalized, blocked, and settlement outcomes. A Perpl acknowledgement alone is not a fill. Existing mock Perp history remains accessible through the mock venue.

## Configuration and acceptance

`backend/.env.local` is ignored by Git. Keep `MONAD_TESTNET_PERPL_AUTONOMY_ENABLED=false` and `MONAD_TESTNET_PERPL_DIRECT_EXECUTION_ENABLED=false` by default. A funded direct run also requires the Testnet action, broadcast, and operator gates. Direct enrollment skips `PERPL_API_ORIGIN`; the API adapter still requires Perpl to whitelist that origin. The adapters pin the Perpl Testnet context to chain `10143`, the exchange, and AUSD token. Market IDs and trading parameters come from that context and related live market endpoints. The current public context states a **100 AUSD** minimum to open an exchange account; the older USDC mock policy does not apply. See [Perpl API configuration](https://github.com/PerplFoundation/api-docs/blob/main/README.md) and [Agora token deployments](https://docs.agora.finance/developer/contract-deployments).

A Monad local fork proved the deployed `execOrder` ABI, delegated-account permissions, IOC long and short entry/close with Exchange fill events, post-only placement and cancellation, failed order handling, and account-state decoding. The live acceptance run then completed three BTC cycles plus two automatic PUMP round trips. Starting collateral was 100 AUSD; 99.732661 AUSD returned, a realized loss of 0.267339 AUSD including 0.155131 AUSD in Perpl fees. The operator separately paid 0.655745964 MON gas for activation, ten orders, and settlement. Finalized Exchange account state has zero collateral, positions and locks; operator access is false. The offline KeePassDX Android setup, unattended Activity updates, owner stop, and final wallet balance were verified. Live limit amend/cancel, linked exits, margin changes, funding and liquidation remain unobserved; the local fork covers placement/cancel. The retained API adapter's REST batch and WebSocket trading remain separate checks after Origin approval. Re-enable funded gates only for a new reviewed acceptance run.
